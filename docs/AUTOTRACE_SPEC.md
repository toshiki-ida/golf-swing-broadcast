# クラブヘッド自動追尾 仕様

任意のスイング動画を入れると、ヘッド軌跡を自動で検出し、軌道を焼き込んだ
動画を出力する。手打ちの軌道ポイント作業を置き換えることが目的。

実装: `autotrace.py` / 検証素材: `rec_0611_130128.mp4` (1920x1080, 29.97p)

---

## 1. スコープ

| | 対応 |
|---|---|
| 入力 | 動画ファイル1本 + 任意で In/Out フレーム |
| 出力 | ①軌道ポイント `[(x, y, frame), ...]` ②焼き込み動画 ③信頼度レポート |
| 想定カメラ | 三脚固定。ゴルファーが1人、フレーム内に収まっている |
| 想定クラブ | ドライバー〜アイアン。ヘッドが背景と異なる明度/彩度で写っている |

`[(x, y, frame), ...]` は既存の `TrajectoryData` がそのまま食える形式なので、
編集タブでの手直しにそのまま流せる。

---

## 2. 入力の自動判定

ユーザーに設定させず、動画から決める。失敗したら**黙って進めず理由を返す**。

| 項目 | 判定方法 | 失敗時 |
|---|---|---|
| カメラ固定か | 背景領域の位相相関シフトが 1px 未満か | 移動 → 手ブレ補正を前置 (§8) |
| ゴルファー | 人物マスクのうち**動き量の合計が最大**のもの | 検出0 → エラー |
| 体格スケール | ゴルファーのシルエットの縦の広がり `Hp` | — |
| ヘッド径 | `Hp / 37` (身長165cm・ヘッド11cm 相当) | — |
| 体からの最小距離 | `Hp / 18` | — |
| ボール位置 | 芝の上の小さく丸い白塊で、後半に消えるもの | 見つからず → アンカー無しで続行 |
| インパクト | ボールの明度が失われ8フレーム戻らない最初のフレーム | 同上 |
| スイング区間 | 追跡できた範囲。In/Out 指定があればその内側 | — |

**重要**: 姿勢推定 (キーポイント) は使わない。手首座標が数百px 飛ぶ事故が
実際に起き、そこから決めた探索範囲ごと壊れた。シルエットは安定している。

## 3. パイプライン

### 3.1 背景 (1パス目)
明度Vと彩度Sの画素ごと中央値。カメラ固定が前提。
横帯ごとに計算する (全フレームを積むとGB級になる)。

### 3.2 証拠マップ (2パス目・フレームは3枚だけ保持)

```
動き    = min(|V_k - V_k±1|) + 1.2 * min(|S_k - S_k±1|)      > 20
証拠 e  = |V_k - bgV| + 1.2 * max(0, bgS - S_k)
          ただし彩度が20以上「上がった」画素は0            … 色物を除外
          ゴルファーのシルエット(前後3フレームの和)を除去
          シルエットからの距離 < Hp/18 を除去
```

- 動きの判定に**彩度も足す**のが必須。暗く色の濃い領域 (紺の服・影) を
  通過する数フレームは、明度差がほとんど出ない
- 背景差の符号は問わない。ヘッドのブレは半透明なので、芝の上では暗く、
  暗い背景の前では明るく写る
- 彩度が落ちる方向だけ加点する。ヘッドは灰色の金属なので必ず彩度が落ちる

### 3.3 体の残りを落とす
前後4フレームで**7回以上**反応した画素を除去。体はゆっくりなので同じ画素に
居座る。しきい値を厳しくしすぎると、**トップ付近でほぼ止まるヘッド自身**を
消してしまうので緩めに取る。

### 3.4 候補
証拠の二値マスクの**内側距離変換**のピーク。シャフトは2-3px、ヘッドは十数px
なので、太い所がそのままヘッドになる。シャフト途中を掴む問題が原理的に起きない。
体から遠いほど加点 (最大0.8)。

### 3.5 追跡 (厳密DP)
観測ペアを状態にした最短経路。

```
コスト = Σ(0.30 - スコア) + Σ|Δv|/200 + 0.35/欠測フレーム
         + 0.020 * max(0, 25 - 速度)      … 止まる経路への罰
         + 0.5 * (始端終端の未カバー分)
```

ボールが見つかっていれば、インパクトのヘッド位置をスコア8の強アンカーにする。

### 3.6 仕上げ
- **信頼度1.5以上の点**だけを確かな観測とみなす
- その点列 + 球位置を通る **PCHIP スプライン**で全フレームを埋める
- 確かな点の位置は、ブレの**形の重心** (明るさ非依存) に吸着させる
- 補間で埋めた区間は動かさない

高速域 (ヘッドが1フレームで数百px動く区間) は証拠が薄く、拾えた点も
信頼できない。そこを無理に検出で埋めず、確かな点と球を通る弧で結ぶ。
手で軌道を置くときと同じ考え方。

---

## 4. 信頼度レポート

フレームごとに `observed / interpolated` と信頼度を返す。UIでは

- 実検出 … 実線
- 補間 … 破線または半透明

で描き分け、**どこが推定かをオペレーターが一目で判断できる**ようにする。
無条件に「できました」と出さない。

---

## 5. 手動補正のワークフロー

自動検出は下書きであって最終形ではない。

1. 自動生成 → `control_points(n)` で12〜15点に間引いて編集タブへ流す
2. オペレーターは既存のポイント編集 (右ドラッグ移動 / 中クリック削除 /
   ベジェハンドル) でそのまま直せる
3. 1点直したら、その点を確かな観測として**再補間**する（再解析は不要）

---

## 6. 出力

| 種別 | 内容 |
|---|---|
| ポイント | `[(x, y, frame), ...]` — `TrajectoryData` 互換 |
| 動画 | 既存の `render_trajectory_on_frame` でフレーム同期描画して書き出し |
| メタ | ボール位置、インパクトフレーム、フレーム毎の信頼度 |

描画設定 (色・太さ・フェード・`end_frame`) は既存のものをそのまま使う。

## 7. CLI / 組み込み

```
python -m autotrace_cli INPUT.mp4 [--in N] [--out N] [--video OUT.mp4]
                                  [--json OUT.json] [--report]
```

アプリ側は編集タブに「自動生成」ボタンを置き、`progress(ratio, message)`
コールバックで進捗を出す。解析はワーカースレッドで走らせ、GUIを止めない。

## 8. 素材が前提から外れる場合

| 状況 | 対策 |
|---|---|
| カメラが動く | 前処理で特徴点マッチによる安定化。背景中央値はその後 |
| ゴルファーが複数/交差 | 動き量最大は誤りうる。In/Out で1スイングに絞る |
| 逆光でヘッドが黒潰れ | 彩度の手がかりが死ぬ。明度差のみで動作するが精度は落ちる |
| 屋内・人工芝 | ボール検出の「芝」条件が効かない。アンカー無しで続行 |
| 左打ち | 左右非対称な処理は入れていないのでそのまま動く |

## 9. 既知の限界（素材由来）

**フレームレートが支配的**。29.97p ではダウンスイングが3〜4フレームしかなく、
ヘッドは1フレームで200〜400px移動する。この区間ではヘッドは「塊」ではなく
薄く長い筋になり、さらにギャラリー前を通過すると背景差も小さい。

検証素材での実測：

| 区間 | 状態 |
|---|---|
| アドレス〜トップ〜切り返し | ヘッドに正確に乗る |
| ダウン〜フォロー前半 | **検出困難。弧で補間** |
| フィニッシュ | 筋の太い部分＝ヘッドに乗る |
| インパクト | ボール位置で確定 |

**60p以上で撮れればこの問題はほぼ消える**。1フレームあたりの移動量が半減し、
ヘッドが塊として写るため。素材の要件として明記する価値がある。

インターレース素材 (1080i59.94) なら、フィールド分離で時間解像度を倍にできる。
既存の `field_processor.py` が使える。

## 10. 処理時間

3.4秒のスイング (103フレーム, 1920x1080) で **約9秒**。

| 段階 | 時間 |
|---|---|
| モデル読込 (起動時1回) | 2.8秒 |
| 読み込み + 背景 | 1.5秒 |
| 人物マスク (10フレームおき, 4枚バッチ) | 2.5秒 |
| 証拠マップ + 候補 | 4秒 |
| DP・仕上げ | 1秒未満 |

速度に効いた設計判断:

- **検出は 0.4 倍解像度で行う** — ヘッドは十数px あるので成立する。画素数が
  1/6 になる。出力座標だけ元の解像度に戻す。0.33 まで下げるとヘッドが
  5px を切って破綻するので、そこが下限
- **人物マスクは10フレームおき** — シルエットはヘッドよりずっとゆっくり
  変わる。間は前後2枚のマスクの和で代用し、和までの距離は各距離マップの
  `min` で求まるので距離変換の再計算も要らない
- **証拠マップは int16** — float32 だと 2M 要素の配列を何度も舐めることに
  なり、ここが律速になっていた
- **DPはベクトル化** — ペアごとの Python ループが数百万回になる。ノード
  単位の numpy 演算にし、ペア構築も `searchsorted` の区間取得にする
- **デコードは2パス** — 背景・キーフレーム・球検出用を1パス目でまとめて回収

`scale` と `seg_every` は引数で変えられる。精度優先なら `scale=0.5,
seg_every=4`、速度優先なら現状値。

## 付録: 実装中に踏んだ罠

同じ失敗を繰り返さないための記録。

1. **暗さの符号を決め打ちした** — ヘッドは黒いと仮定したが、半透明のブレは
   暗い背景の前では明るく写る。`|差|` にすべき
2. **人物マスクを膨張させた** — ギャラリーごと消して、その前を通過する
   クラブが丸ごと欠測になった。ギャラリーは静止しているのでマスク不要
3. **姿勢キーポイントに依存した** — 手首が別人に飛び、そこから決めた
   探索範囲ごと壊れた。シルエットだけ使う
4. **ゴルファーを「画面中央に近い人物」で選んだ** — 腕を伸ばした瞬間に
   隣の人物へ乗り換えた。動き量の**合計**で選ぶ
5. **動きの判定を明度だけで行った** — 暗い服の前を通過する数フレームで
   ゲートに落ちた。彩度も足す
6. **連結成分の重心をヘッドとした** — 細いシャフトを含むので重心がずれる
7. **明るさで重み付けして重心を取った** — クラウンの反射に引っ張られた
8. **「ヘッドは止まらない」と仮定しすぎた** — トップではほぼ止まる
